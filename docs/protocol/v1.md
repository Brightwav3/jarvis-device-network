# Protocol v1

## Compatibility

Every message has `protocol_version: "1"`. Version 1 accepts only that exact value. A sender using another string receives the structured `UNSUPPORTED_PROTOCOL_VERSION` error; no compatibility guessing occurs.

## Common envelope

Every application message contains a non-empty `message_id`, ISO 8601 UTC `timestamp`, `type`, and typed `payload`. All post-registration messages additionally contain a stable `device_id` and ephemeral `session_id`.

```json
{
  "protocol_version": "1",
  "type": "device.heartbeat",
  "message_id": "m-heartbeat-01",
  "timestamp": "2026-08-10T10:00:00.000Z",
  "device_id": "bedroom-01",
  "session_id": "s-01",
  "payload": {}
}
```

## Registration

Registration declares stable identity, optional descriptive metadata, and machine-readable capabilities. It has no session fields because a session is established only after registration succeeds.

```json
{
  "protocol_version": "1",
  "type": "device.register",
  "message_id": "m-register-01",
  "timestamp": "2026-08-10T10:00:00.000Z",
  "payload": {
    "device_id": "bedroom-01",
    "device_type": "room_satellite",
    "name": "Bedroom satellite",
    "room": "bedroom",
    "software_version": "0.1.0",
    "capabilities": ["audio.input", "audio.output"]
  }
}
```

## Other typed messages

- `device.heartbeat`: empty object payload.
- `device.event`: `{ "event": string, "payload": object }`.
- `command.request`: command ID, target capability, operation, and object arguments.
- `command.result`: command ID, outcome flag, and optional object result or structured error.

## Validation and errors

`parseDeviceMessage(value, maxBytes?)` is the runtime entry point for untrusted JSON-compatible input. It accepts only known types and strict envelope/payload shapes, checks non-empty identifiers and ISO timestamps, and applies a default 64 KiB serialized-message limit. It never throws for malformed input.

```json
{
  "ok": false,
  "error": {
    "code": "UNSUPPORTED_PROTOCOL_VERSION",
    "message": "Unsupported protocol version",
    "context": { "protocol_version": "2" }
  }
}
```

Defined validation error codes are `INVALID_MESSAGE`, `UNSUPPORTED_PROTOCOL_VERSION`, and `MESSAGE_TOO_LARGE`.
